Abas acessíveis (ARIA) com conteúdo inline

No Projeto Dark Souls, o conteúdo trocava ao clicar em botões, e cada seção era buscada com fetch. Funcionava, mas tinha problemas. Esta anotação explica por que troquei por abas com o texto já dentro do HTML e como montei o padrão ARIA de abas.

Por que sair do fetch

  • Frágil: imagens das seções quebraram porque os caminhos (../assets/...) eram resolvidos a partir da página principal, e não do arquivo carregado.
  • Mais lento a cada clique: toda troca pedia um arquivo ao servidor.
  • Pouco indexável: a área de conteúdo começava vazia, então o texto aparecia só depois de um clique.
  • Pouco acessível: botões comuns não dizem ao leitor de tela que existe um grupo de abas.

A estrutura HTML

Cada botão é uma tab, e cada bloco de conteúdo é um tabpanel. Os atributos ligam um ao outro.

<nav class="nav-buttons" role="tablist" aria-label="Temas de Dark Souls" hidden>
  <button type="button" role="tab" id="tab-lore" aria-controls="lore"
          aria-selected="false" tabindex="-1" class="btn">Lore</button>
  <!-- demais abas -->
</nav>

<div id="lore" role="tabpanel" aria-labelledby="tab-lore" tabindex="0">
  <!-- conteúdo da aba -->
</div>
  • aria-controls aponta da aba para o painel, e aria-labelledby faz o caminho inverso.
  • aria-selected indica a aba ativa.
  • tabindex="-1" nas abas inativas: só a aba ativa entra na ordem do Tab. As outras são alcançadas pelas setas (técnica chamada roving tabindex).
  • O nav começa com hidden e o JavaScript o mostra. Sem JavaScript, os botões somem e todo o conteúdo fica visível.

O JavaScript

const tablist = document.getElementById('nav-anchor');
const tabs = Array.from(tablist.querySelectorAll('[role="tab"]'));
const panels = tabs.map(tab => document.getElementById(tab.getAttribute('aria-controls')));

function ativarAba(indice, { foco = false, atualizarHash = true } = {}) {
  tabs.forEach((tab, i) => {
    const ativa = i === indice;
    tab.setAttribute('aria-selected', ativa);
    tab.tabIndex = ativa ? 0 : -1;
    panels[i].hidden = !ativa;
  });
  if (foco) tabs[indice].focus();
  if (atualizarHash) history.replaceState(null, '', '#' + panels[indice].id);
}

Teclado

As setas movem entre as abas, e Home e End vão à primeira e à última.

tab.addEventListener('keydown', e => {
  const ultimo = tabs.length - 1;
  const teclas = {
    ArrowRight: i === ultimo ? 0 : i + 1,
    ArrowLeft:  i === 0 ? ultimo : i - 1,
    Home: 0,
    End: ultimo
  };
  if (e.key in teclas) {
    e.preventDefault();
    ativarAba(teclas[e.key], { foco: true });
  }
});

Endereço por aba

Com history.replaceState cada aba ganha um endereço (#lore, #folclore) sem poluir o botão "voltar". Ao abrir a página com um desses endereços, a aba correspondente já aparece ativa, e o evento hashchange cobre os links internos do menu e do rodapé.

Armadilhas que encontrei

  • hidden some se o CSS definir display. Um display: flex na classe do nav anulava o atributo. A correção é uma regra [hidden] { display: none !important; }.
  • Imagens em painéis escondidos. Com loading="lazy" elas só são baixadas quando a aba aparece, então a primeira carga continua leve.
  • Foco visível. Defina um :focus-visible nos botões e nos painéis. Sem ele, quem usa o teclado não sabe onde está.

Como testar

  • Navegue só com o teclado: Tab, setas, Home e End.
  • Abra a página com um endereço, como #folclore.
  • Desative o JavaScript e confira se todo o texto continua visível.
  • Teste com um leitor de tela (NVDA ou VoiceOver): ele deve anunciar "aba 2 de 5".

Resultado

Troca instantânea, sem requisições extras, texto no HTML para os buscadores e navegação completa pelo teclado. O artigo "Filosofia da Transitoriedade", que antes esticava a página, virou a quinta aba.
